## 2. Frozen policy decisions (Engineer 2/3 binding notes)

1. **64-byte uniform stride.** Every transcoded financial message — ITCH *and*
   OUCH — lands in a 64-byte projection (`weft_itch_msg_t` / `weft_ouch_msg_t`):
   16-byte header + 48-byte body union. This mirrors Pillar 4's WHP2 lane width so
   projected messages can be written into Hot-Plane lanes with one aligned store,
   no packing logic. Memory amplification (19–50 byte wire → 64 B) is the accepted
   cost of O(1) lane writes and cache-line-aligned iteration; measured decode
   throughput (§4) shows it is not a bottleneck (60+ M msg/s).
2. **Natural alignment for scalars, `_Alignas(64)` for batches.** The structs
   themselves carry natural alignment (`_Alignof == 8`); the 64 B guarantee is
   realized through the batch-declaration contract (`WEFT_ALIGNED64` /
   `aligned_alloc(64, n*64)`), enforced at runtime by `WEFT_ADAPTER_EALIGN`.
   Single-message decode requires natural 8-byte alignment only.
3. **SBE dimension encoding pinned to u8 block_length + u8 num_in_group** and
   var-field length prefix pinned to u8 — legal SBE encodings, frozen for the
   descriptor ABI. Schemas using other dimension encodings transcode at the seam.
4. **SBE strict-match policy (v0)**: wire template/schema/version/block_length
   must equal the schema descriptor exactly. Forward-compat block growth is a
   declared follow-up (needs offset-aware field skipping).
5. **ITCH validation policy** (always on, both strict and lenient framings):
   timestamp < 24 h, enumerated chars (side/state/action/cross-type/...),
   printable-ASCII symbol fields, non-zero share quantities on volume messages,
   unknown type → `EBADMSG`. All validation happens on wire bytes BEFORE the
   projection is written, honoring the frozen contract *"on any negative status
   the output message is left untouched"* — proven by oracle check O8.
6. **Prices stay raw integer ticks** (4-decimal wire value) in the ABI;
   `weft_itch_price_d()` is the only float conversion (display-side).

### 3.4 Padding proof (Law 2)

* **82 `_Static_assert`s** in the frozen header pin every struct size and every
  scalar field offset at compile time — the ABI cannot drift silently in any
  compiler (gcc 14.2 and clang 19.1 both verified; the asserts fired for real
  during development, catching two miscounted padding arrays — see §7).
* No misaligned 64-bit loads are ever emitted: wire fields are read via
  `memcpy()` into locals + `__builtin_bswap*` (compilers fold to a single
  unaligned `mov`); projections store u64s only at offsets ≡ 0 (mod 8).
* Union member max-alignment is 8; the 64-byte stride is preserved for batches
  because `sizeof == 64` exactly (asserted: `sizeof % 64 == 0`).
* SBE descriptors: `field_desc` = 8 B, `group_desc` = 8 B, `schema` = 40 B
  (pointer offsets 16/24/32 asserted) — stable for FFI descriptor tables.

## 5. Endianness & byte-order transformation

* **ITCH/OUCH/MoldUDP64/WAF**: all big-endian on wire. Loads go through
  `weft_load_be16/32/48/64` = `memcpy` + `__builtin_bswap{16,32,64}` on LE
  hosts (identity on BE hosts via `__BYTE_ORDER__` guard). The BE48 timestamp
  is assembled arithmetically (endian-independent).
* **SBE**: little-endian per the SBE default; mirrored loaders
  (`weft_load_le*`) with the same conditional-bswap discipline.
* **Empirical transform rate** (§4 last row): the BE64 wire→host path sustains
  12–28 GB/s in isolation; the integrated decode paths (60–124 M msg/s over
  19–50 byte messages ≈ 1.2–2.5 GB/s of wire bandwidth per surface) are
  dominated by validation + projection stores, not byte-order work.
* **CRC endianness note**: x86 `crc32` and ARMv8 `crc32c` instructions consume
  little-endian multi-byte operands, which matches the reflected-CRC byte order
  on both targets; the slicing-by-8 reference interleaves lanes identically.
  Cross-verified bit-exact against hardware on 512 random slices + 128
  unaligned tails (K2), including the normative vectors
  `crc32c("123456789") == 0xE3069283` and `crc32c(32×00) == 0x8A9136AA`.
* **Adler-32 SSE2 kernel derivation** (provable identity, validated by K5
  sweep incl. every length 0–64 and the 4090–4102 reduction-boundary window):
  per 16-byte chunk, `acc_w += acc_s1` **before** the sad add (age term),
  `acc_dot += madd_epi16(unpack(chunk), [16..1])` (intra-chunk weights), then
  reduce mod 65521 every 256 chunks with lane bounds ≤ 2²⁷:
  `s1 = hsum(acc_s1)` (lane0 seeded with s1₀), `s2 = s2₀ + 16·hsum(acc_w) + hsum(acc_dot)`.

## 7. Defect log (self-review catches, all fixed pre-commit)

1. **Header padding miscounts** — both `order_replace` bodies declared
   `_pad0[28]` where only 24 bytes remain; caught immediately by the frozen
   `_Static_assert` table on first compile. (The assert net works.)
2. **OUCH offset drift** — body fields written one byte past their pinned
   offsets (timestamp occupies m[1..6], so `order_ref` lands at m+7, not m+8);
   caught in self-review before first compile; offsets now documented in a
   comment block next to the decoder.
3. **Dead EBOUNDS check** — `num_in_group` is u8, so a `> 4096` comparison is
   statically false; gcc `-Werror=type-limits` flagged it. EBOUNDS remains
   enforced where reachable (accessor bounds, projection symbol length).
4. **Adler-32 SSE2 age-term bug** — `acc_s1` started at zero instead of being
   seeded with s1₀, dropping `16·K·s1₀` from s2; the K5 vectorized-vs-portable
   cross-check caught it with the exact predicted fingerprint
   (deficit = 16·⌊len/16⌋ per reduction block). Kernel fixed + derivation
   documented in §5.
5. **Test-harness defects caught by the suite itself**: OUCH golden encoder
   never wrote the type byte (stale-buffer leak across fixture builds); PCAP
   record headers written *after* packet bytes instead of before; negative-path
   tests hardcoded the 'A'-message offset instead of computing it; `ferror()`
   after `fclose()`; fuzz intact-baseline invariant initially applied to
   mutated inputs; fuzz determinism compared against a dirty (non-zeroed)
   batch; bench Mmsg/s arithmetic off by 10³; mold bench passed `msg` instead
   of `msg−2` to the LENPREFIX decoder; bswap microbench dead-code-eliminated;
   fixture regeneration when the fixtures directory itself was missing
   (runner now `mkdir -p`, walk now bounds-guarded).

## 9. Declared boundaries / follow-ups

1. **OUCH 5.0 field maps** are pinned per spec recollection ('S' 8 B, 'A' 46 B,
   'E' 27 B, 'C' 32 B, 'X' 19 B, 'U' 31 B). Cross-validation against an official
   OUCH 5.0 capture is the declared follow-up for Engineer 2's rmw_weft seam;
   the fail-closed length-prefix gate contains any layout drift.
2. **aarch64 runtime dispatch** for CRC32C uses the compile-time
   `__ARM_FEATURE_CRC32` path only (no `getauxval` probe); aarch64
   cross-compilation was not possible in this sandbox (no cross toolchain) —
   code paths are guarded and the portable fallback is always available.
3. **SBE forward-compat block growth** (wire block_length > schema) is refused
   with ESCHEMA under the frozen v0 strict-match policy.
4. **NEON Adler-32** is left as a follow-up (portable kernel covers aarch64
   correctly; x86_64 gets the SSE2 kernel).
5. AVX2/AVX-512 CRC folding (PCLMULQDQ-based) would push CRC-32C well past the
   current 8.5 GB/s but was not required to clear any bar; SSE4.2 hardware CRC
   satisfies the directive's checksum duties.
