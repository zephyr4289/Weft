THE TRIAD PROTOCOL

Site digest — every mechanism quoted verbatim from WHITEPAPER §3 with live pointers

The problem each layer fails at

Single buffer tears. Double buffering fixes tearing but adds back-pressure: a slow reader stalls the writer. Triple buffering removes both problems — if nobody can ever observe a stale view of who owns which buffer. That sentence is the entire content of the protocol.

The protocol (verbatim, WHITEPAPER §3.2)

writer.publish(seq, payload_len):
    if revoked.load(Relaxed):                      # §6: checked FIRST
        epoch.fetch_add(1, AcqRel)                 # ACK
        return DROPPED_REVOKED
    write envelope (v1, seq, payload_len) into buf[w_work]
    write canary = seq at buf[w_work].tail
    old = latest.exchange(w_work, AcqRel)          # THE atomic
    w_work = old
    return PUB_OK

reader.claim():
    mine = latest.exchange(r_work, AcqRel)         # THE atomic
    r_work = mine
    return mine    # read buf[mine] IN PLACE; held until next claim

Why it is wait-free

  • publish(): write payload into the writer-owned buffer, then one exchange(AcqRel). No loop, no branch on contention — bounded steps regardless of reader behavior (Law 1).
  • claim(): one exchange takes latest → returns the buffer to the writer next time. The returned frame is always the freshest published one; superseded frames were never queued (drop-not-queue).
  • No ABA: the same slot index can only reappear after its buffer has been fully reclaimed and rewritten under a fresh happens-before edge created by the exchanges themselves.
