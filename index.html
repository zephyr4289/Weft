§1. THE PROBLEM

Hot State Breaks Reactive UI

When a 60–240 Hz data stream pushes through React `setState`, Flutter `setState`, or SwiftUI `@Published`, garbage collection spikes and re-render cascades destroy frame budgets.

REACTIVE PATH (setState) Heap Allocation per Tick
// 60 Hz tick -> allocation -> re-render
const [state, setState] = useState(data);
onTick((sample) => setState(sample)); // ❌ GC Jitter
  • GC Allocations: ~1.2 MiB / sec
  • Frame Budget: Violations at 60 Hz
  • Torn Reads: Possible under multi-threading
WEFT CONTINUOUS PLANE Zero-Copy Off-Heap Channel
// 240 Hz tick -> zero-alloc -> draw-phase read
const plane = useHotPlane(buffer);
engine.tick(); // ✅ 0 B heap growth
  • GC Allocations: Exact 0 Bytes
  • Frame Budget: Pinned at 240 Hz (< 4.16ms)

§3. THE MECHANISM

The Triad Protocol

3 buffers + 1 atomic latest.exchange(AcqRel). Wait-free in both directions, latest-wins, zero torn claims.

SLOT A

Reader Active

Consumer reads from committed immutable snapshot without holding locks.

ATOMIC LATEST

exchange(AcqRel)

Writer publishes latest slot index atomically in a single release instruction.

SLOT B / C

Writer Active

Producer writes to free slot. Never blocks consumer, never overwrites active read.

Formally Verified Invariants (TLA+ Checked)

I1 No torn reads: Payload written before the swap (AcqRel orders it); reader reaches a buffer only via a swap that transferred exclusive ownership
I2 Wait-free writer: Single `exchange` — no spin, no retry, no CAS loop
I3 Wait-free reader: Single `exchange` — no spin, no retry, cannot fail
I4 Latest-wins: `latest` names the freshest publish; claims take `latest`
I5 No back-pressure: Writer needs only its private `w_work`, refreshed by its own swap
I6 No use-after-free across FFI: `revoked` set (Release) before free; writer checks per publish (one Relaxed load); free deferred until writer quiescence
